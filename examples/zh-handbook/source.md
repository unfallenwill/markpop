# 值班手册

**适用对象**：值班工程师
**修订日期**：2026-10-01

本手册覆盖发布流水线、告警目录和升级路径。手册按 A4 排版，章节编号、表格宽度都
按打印场景做过收敛。

## 一、发布流水线

每次向 `main` 合并都会触发下面的流水线。没有事故记录，任何一个阶段都不允许跳过。

| 阶段 | 超时 | 失败后动作 |
|---|---|---|
| `build` | 10 分钟 | 重试一次，仍失败则呼叫值班 |
| `integration` | 20 分钟 | 重试两次，仍失败则呼叫值班 |
| `canary` | 30 分钟 | 自动回滚，并呼叫值班 |
| `promote` | 10 分钟 | 自动回滚，并呼叫值班 |

### 1.1 本地执行

```bash
cargo run --release -- pipeline.toml --dry-run
cargo run --release -- pipeline.toml --stage integration
```

`--dry-run` 只打印解析后的执行计划，不会连接集群。

### 1.2 金丝雀规则

金丝雀承接 5% 流量，持续十分钟。三个条件同时满足才会自动晋级：

- 错误率低于 0.1%；
- p99 延迟低于 250 毫秒；
- 饱和度计数器没有新增严重告警。

任何一条不满足，发布立即回滚到上一个版本，并通知值班工程师。

> 回滚永远是安全动作。宁可先回滚再排查，也不要在原地调试。

## 二、告警目录

| 告警 | 级别 | 含义 | 第一动作 |
|---|---|---|---|
| `pipeline-stalled` | P2 | 某阶段超时 | 查看运行日志 |
| `canary-error-rate` | P1 | 金丝雀错误率超过 0.1% | 执行回滚 |
| `saturation-critical` | P1 | 集群已饱和 | 先扩容，再回滚 |
| `cert-expiry-30d` | P3 | 证书即将过期 | 走续期流程 |

### 2.1 屏蔽规则

屏蔽告警必须在备注里带上工单号：

```bash
alertctl mute pipeline-stalled --until 2h --reason "INC-4821"
```

屏蔽会到期自动解除，不存在永久屏蔽。

## 三、升级路径

1. 主值班在五分钟内确认告警。
2. 十五分钟内无人确认，呼叫备班。
3. 三十分钟内无人确认，呼叫事故经理。

### 3.1 联系方式

升级走内部目录里的值班轮转表。个人联系方式不要写进本手册。

## 四、事故复盘清单

- [ ] 二十四小时内写完时间线
- [ ] 找到促成因素，而不只是直接触发因素
- [ ] 能补测试的地方补上回归测试
- [ ] 在事故记录里关联后续工单

## 附录 A：常见问题

**可以跳过金丝雀吗？** 不可以。所有晋级路径都包含金丝雀阶段。

**晋级已经完成了还能回滚吗？** 可以。任何时候回滚都是受支持的操作，把它当作第一
响应手段也完全合理。

**如果回滚本身失败了怎么办？** 立即升级，不要在自动回滚失败的基础上再叠加一次
手工回滚。
